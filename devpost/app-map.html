What it is

A Gmail Add-on (Google Apps Script) that extracts the ontological ABox of the open email with Gemini, grounded in a gist TBox subset, and turns commitments into Google Tasks. Four moving parts:

  • Code.gs — entry triggers and action handlers (process, create tasks, preserve).
  • Cards.gs — the CardService UI (home, parking lot, actionables, states).
  • GeminiService.gs — the LLM call and JSON-LD parse.
  • tbox.gs — the gist ontology subset injected into the prompt.

One action, end to end: pressing “Procesar correo”

The ABox then branches: commitments become editable actionables (→ onCreateTasks → Google Tasks), and Preservar writes a Markdown file into Drive/OntoMail/ (→ onPreserve).

A 2-stop reference route

Open the project in your editor and follow the Process action. (Reference route — paths and symbols verified against the finished source.)

Stop 1 — the entry point

Code.gs → onProcess(e). Reads the open message (readCurrentEmail), calls extractAbox, and branches: commitments → buildResultsCard, none → buildNoActionablesCard, failure → buildErrorCard (with Reintentar). This is where a new behavior on “process” would start.

Stop 2 — the LLM contract

GeminiService.gs → extractAbox builds the prompt from tbox.gs (buildTboxPromptBlock) and asks Gemini for JSON-LD matching buildAboxResponseSchema. The retry on 503/429 lives here.

To change this, start here

  • Add or rename a gist type: tbox.gs (ONTOMAIL_TBOX.classes and the schema enum) + the accent in Cards.gs (TYPE_ACCENTS, TYPE_ORDER).
  • Change what a created task contains: Code.gs → onCreateTasks (the task object passed to Tasks.Tasks.insert).
  • Change the preserved Markdown or its folder: Code.gs → buildAboxMarkdown and getOntoMailFolder.
  • Switch the model: no code change — set GEMINI_MODEL in Script Properties.

A practice to reuse

When an integration behaves differently from your mental model, make the real data observable before patching. The “No seleccionaste ningún compromiso” bug came from assuming the switch arrived in e.formInputs; the fix read the documented flat e.formInput map, and a one-line JSON.stringify(e) dump turned guesswork into fact. The same move resolved the Gemini 404/503 (a listModels() call and an error message that names the model). Evidence: the Revisions section of devpost/checklist.md and the self-check tests/form_inputs_check.js, which now pins both input shapes.
